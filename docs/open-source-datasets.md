# Open-Source Data Plan

This benchmark uses a small local seed fixture for deterministic tests and maps
each case to an open-source dataset family that can be converted into the same
schema for larger experiments.

The seed fixture is:

- `data/open_source_fixtures/protocol_memory_seed.json`

The fixture records are synthetic and schema-compatible. They are not a
redistribution of full upstream datasets. This keeps the repository small and
avoids silently repackaging third-party data whose license or redistribution
terms may differ across releases.

## Unified Case Schema

Each benchmark case should have:

- `id`: stable case id.
- `scenario`: one of the benchmark scenarios.
- `source_ids`: open-source source ids that motivated or supplied the case.
- `task`: oracle fields and task-specific requirements.
- Optional `agents`, `evidence`, `memories`, `updates`, or `noise` arrays.

The simulator intentionally evaluates protocol behavior rather than dataset
leaderboard accuracy. A raw dataset row should be converted into a protocol case
with explicit oracle fields such as required evidence ids, allowed memory ids,
forbidden memory ids, conflict outcomes, and critical facts.

## Scenarios

- `capability_market`: tests proof-carrying capability cards.
- `capability_deception`: tests stale, revoked, or misleading capability cards.
- `evidence_synthesis`: tests evidence capsules, provenance, and replayability.
- `evidence_conflict`: tests conflicting, outdated, or adversarial evidence.
- `delegation_drift`: tests commitment receipts and premature terminal states.
- `scoped_memory_privacy`: tests memory scope and leakage control.
- `shared_memory_consistency`: tests concurrent memory update handling.
- `cross_session_rehydration`: tests useful recall, invalid recall, and forgetting.
- `context_manifest_stress`: tests context manifests and artifact references.

## Expansion Path

1. Download or reference raw upstream data outside this repository.
2. Convert a small slice into the unified case schema.
3. Run `node benchmarks/protocol_memory_benchmark.mjs --data path/to/cases.json`.
4. Keep paired seeds across protocols.
5. Report both protocol-level metrics and dataset source metadata.

## Current Raw-Derived Headline Slice

The current headline slice is generated by:

```bash
npm run raw:build:hard10
```

Inputs downloaded through the Hugging Face Dataset Viewer:

- `data/raw_sources/hotpotqa_distractor_validation_rows20.json`
- `data/raw_sources/magpie_train_rows20.json`

Output:

- `data/raw_derived/protocol_memory_raw_derived_hard10.json`

Coverage:

- `capability_deception`: 10 MAGPIE-derived cases.
- `evidence_conflict`: 10 HotpotQA-derived cases.
- `delegation_drift`: 10 MAGPIE-derived cases.
- `scoped_memory_privacy`: 10 MAGPIE-derived cases.
- `context_manifest_stress`: 10 HotpotQA-derived cases.

The conversion is raw-derived rather than raw leaderboard evaluation: upstream
rows provide scenario text, supporting facts, agents, constraints, deliverables,
and privacy context; deterministic protocol-oracle transforms add hidden fields
needed to test capability proof, commitment receipts, scoped memory, and context
manifests.

## Selected Standalone Raw-Derived Benchmark: HotpotQA

The first standalone open-source raw-derived benchmark is HotpotQA evidence and
context stress:

```bash
npm run raw:build:hotpotqa:validation
npm run raw:bench:hotpotqa:validation:dryrun
npm run raw:check:hotpotqa:validation
```

Artifacts (produced locally by the commands above; not committed to this repository):

- `data/raw_sources/hotpot_dev_distractor_v1.json`
- `data/raw_derived/protocol_memory_hotpotqa_validation_evidence_context_full.json`
- `results/hotpotqa-validation-raw-derived-dryrun-summary-seed2061.json`
- `results/hotpotqa-validation-raw-derived-check.md`

Coverage:

- 7,405 `evidence_conflict` cases.
- 7,405 `context_manifest_stress` cases.
- 88,860 dry-run protocol-case evaluations.

This track is intentionally narrower in scenario type than the five-scenario
hard slice, but it now uses the full official HotpotQA distractor dev set. Its
purpose is to provide a clean, attributable, open-source-derived benchmark
where provenance and context-management claims can be inspected independently.
